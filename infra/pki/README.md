# infra/pki: центр сертификации и секреты

Внутренний трафик стенда зашифрован: между сервисами mTLS, к PostgreSQL, Redis и Kafka TLS ([ADR-022](../../docs/05-architecture/adr/ADR-022-internal-traffic-encryption.md)). Сертификаты и секреты создаются командами из этого каталога. В Git нет ни одного ключа и пароля, проверка в CI ([ST-14](../../docs/08-testing/test-strategy.md)).

## Быстрый старт

```bash
make certs        # центр сертификации (если его нет) и сертификаты всех контейнеров
make secrets      # пароли и ключи по перечню
make pki-verify   # проверка: цепочка, алгоритм, срок, имена, ключи, уникальность секретов
make pki-status   # сколько дней осталось у каждого сертификата
make pki-test     # тесты самого скрипта
```

Нужны Python 3 и `openssl` 3. Внешние пакеты не нужны. Команды безопасно повторять: действующее не перевыпускается.

## Что создаётся и где лежит

| Что | Где | Права | Попадает в контейнер |
| --- | --- | --- | --- |
| Закрытый ключ центра сертификации | `.pki/ca.key` | `0400` | Нет. Нужен только при выпуске |
| Сертификат центра сертификации | `.pki/ca.crt` и `secrets/tls_ca.crt` | `0444` | Да, всем (проверка цепочки) |
| Ключ и сертификат контейнера | `secrets/tls_<контейнер>.key`, `secrets/tls_<контейнер>.crt` | `0444` | Только в свой контейнер |
| Пароли, ключи шифрования, секреты подписи | `secrets/<имя>` по [inventory.json](inventory.json) | `0444` | Только тем контейнерам, которые указаны в `readers` |

Каталоги `.pki/` и `secrets/` в `.gitignore`. Каталог `secrets/` создаётся с правами `0700`.

**Почему файлы секретов `0444`, а не `0400`.** Compose монтирует файл секрета в контейнер с правами и владельцем хоста, а процессы в контейнерах работают под другими пользователями (UID 10001 у сервисов, 999 у PostgreSQL). При `0400` и чужом владельце процесс не прочитает свой секрет. Защита построена иначе: каталог `secrets/` доступен только владельцу на хосте, а контейнер получает ровно те файлы, которые смонтированы ему в `compose.yaml`. Если на сервере нужны `0400`, сделайте `chown` файлов на UID пользователя контейнера и задайте `DGM_SECRET_MODE=0400`. Для PostgreSQL и других образов, которым нужен свой владелец ключа, копирование ключа в память контейнера делает их сценарий запуска (шаг 6 плана Ф3).

## Параметры сертификатов

| Параметр | Значение | Основание |
| --- | --- | --- |
| Алгоритм | ECDSA, кривая P-256, подпись SHA-256 | ADR-022 |
| Центр сертификации | Свой, один, срок 5 лет, `pathlen:0` | ADR-022 |
| Сертификат контейнера | Срок 90 дней, назначения `serverAuth` и `clientAuth` (контейнер и сервер, и клиент), без права выпускать сертификаты | ADR-022 |
| Имена | `CN` равен имени контейнера в сети. SAN: `DNS:<контейнер>`, `DNS:localhost`, `IP:127.0.0.1` и добавочные имена из перечня | ADR-022 |
| Формат | PEM, ключ в виде PKCS#8 без пароля | Подходит Java, PostgreSQL, Redis, Kafka и nginx |
| Обновление | `make certs` перевыпускает сертификаты, у которых осталось меньше 30 дней или цепочка и ключ не подходят. Оповещение за 14 дней: `make pki-verify` падает | ADR-022 |

**Идентичность вызывающего сервиса это `CN`.** Фильтр `caller-filter` берёт имя из `CN` сертификата клиента и сверяет со списком `x-allowed-callers` маршрута. SAN с `localhost` нужен только для проверки готовности внутри контейнера.

## Как добавить контейнер или секрет

1. Дописать запись в [inventory.json](inventory.json): контейнер в `containers` (разовое задание без сертификата в `jobs`), секрет в `secrets` (вид `password`, `key32` или `hex32`, перечень `readers`).
2. `make certs secrets pki-verify`.
3. Смонтировать секрет в `compose.yaml` только перечисленным читателям. `check_compose.py` сверяет монтирование с перечнем.

## Перевыпуск и компрометация

| Ситуация | Что делать |
| --- | --- |
| Подходит срок сертификатов | `make certs`, затем перезапуск контейнеров (`make up` подхватывает файлы). Spring Boot перечитывает сертификаты без перезапуска |
| Секрет скомпрометирован | `python3 infra/pki/dgm_pki.py secrets --force`, затем пересоздание ролей и перезапуск. Ключи шифрования (`inventory_kek`) меняются с перешифровкой DEK по [ADR-009](../../docs/05-architecture/adr/ADR-009-key-encryption-hmac.md), не простой заменой |
| Ключ центра сертификации скомпрометирован | Удалить `.pki/`, `make certs` с `--force` (`python3 infra/pki/dgm_pki.py certs --force`), перезапустить всё |
| Потерян `.pki/ca.key` | Тот же порядок: новый центр и перевыпуск всех сертификатов |

## Тесты

`test_pki.py` проверяет на временных каталогах: цепочку для обоих назначений, алгоритм и кривую, SAN и `CN`, срок 90 дней, отказ для сертификата чужого центра, выявление ключа от другого сертификата, перевыпуск истекающего и сохранение действующего, уникальность и длину секретов, права файлов, отсутствие ключа центра среди секретов, `.gitignore`. Запуск: `make pki-test`.
