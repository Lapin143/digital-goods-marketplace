# infra/postgres

PostgreSQL 16 (образ `postgres:16.15-trixie`), один экземпляр на семь баз (шесть сервисов и Keycloak, [ADR-002](../../docs/05-architecture/adr/ADR-002-microservices-consolidation.md)).

| Файл | Назначение |
| --- | --- |
| `postgresql.conf` | Память по бюджету (`shared_buffers` 128 МБ, `max_connections` 100, `work_mem` 4 МБ), TLS от 1.2, `scram-sha-256`, журнал в стандартный вывод |
| `pg_hba.conf` | Сокет внутри контейнера без пароля (инициализация и проверка готовности), по сети только `hostssl` и пароль, `hostnossl` отвергается |
| `entrypoint.sh` | Копирует ключ сервера в `tmpfs` с правами 0600 (PostgreSQL не принимает ключ с чужими правами, а секреты Docker монтируются с правами хоста) и запускает штатный сценарий образа |
| `roles.json` | Единственный перечень баз, ролей, секретов и пределов соединений. Читает `init/10-databases-and-roles.sql`, сверяет `tools/docs-checks/check_db_roles.py` |
| `init/10-databases-and-roles.sql` | Создаёт базы и роли при первом запуске пустого тома (каталог смонтирован в `/docker-entrypoint-initdb.d`), повторяется командой `make db-roles` |

## Как это работает

- **Запуск без root.** Контейнер работает под UID 999 с файловой системой только для чтения. Сокет PostgreSQL, каталог ключей и `/tmp` лежат в `tmpfs`, данные в томе `pgdata`.
- **TLS.** Клиент подключается с `sslmode=verify-full` и корневым сертификатом `tls_ca.crt`. Имя в сертификате сервера `postgres`, также есть `localhost` и `127.0.0.1` (отладка).
- **Аутентификация.** Администратор `postgres` (пароль `db_postgres_admin`) нужен только для инициализации. Сервисы ходят под своими ролями, без прав суперпользователя.
- **Готовность.** `pg_isready` по TCP на `127.0.0.1`. На время инициализации сервер слушает только сокет, поэтому TCP-проверка не даёт ложной готовности.
- **Архив журнала транзакций** (`archive_mode`, том `pgarchive`) включается в Ф6 вместе с резервным копированием ([c4-deployment.md](../../docs/05-architecture/c4-deployment.md), решение 11).

## Базы и роли

| Что | Сколько | Как устроено |
| --- | --- | --- |
| Базы | 7 | `catalog_db`, `inventory_db`, `order_db`, `payment_db`, `delivery_db`, `platform_db` и `keycloak_db`. Владелец базы сервиса её роль-мигратор, владелец `keycloak_db` роль `keycloak` |
| Роли-мигратор `migrator_<сервис>` | 6 | Применяют миграции Flyway при старте сервиса: создают схемы, таблицы, выдают права. Не суперпользователь, не создают роли и базы, не читают файлы сервера. Предел соединений 2 |
| Рабочие роли `app_<модуль>` | 11 | Ходят сервисы во время работы. Права на таблицы только своей схемы выдают сами миграции (раздел «Роли и права»), создавать объекты не могут. Предел соединений равен пулу модуля: `catalog` 5 и `seller_onboarding` 3, остальные сервисы 8 (у `platform-service` поровну между пятью: 2, 2, 2, 1, 1) |
| Роль `keycloak` | 1 | Владелец `keycloak_db`, предел 10 |

Подключаться к базе могут только её владелец и её рабочие роли: у `PUBLIC` право `CONNECT` отозвано, у служебной базы `postgres` тоже. Пароли читаются из файлов `/run/secrets/db_<имя роли>` на стороне сервера, в окружение, команды и журнал не попадают (`log_min_error_statement` на время скрипта отключён).

Скрипт безопасно запускать повторно: он создаёт недостающее, а у существующих ролей заново выставляет атрибуты, предел и пароль из секрета. После замены секрета (`make secrets`, затем перевыпуск) достаточно `make db-roles`. Новая роль добавляется в `roles.json`, секрет в `infra/pki/inventory.json` и compose, затем `make db-roles`.

Порядок первого запуска: контейнер стартует, штатный сценарий образа создаёт кластер и запускает временный сервер, выполняет `init/*.sql`, перезапускает сервер уже с сетью. Готовым контейнер считается после этого (проверка по TCP). Сервис при старте подключается ролью-мигратором и применяет миграции, затем открывает пул рабочей роли.

## Подключиться с хоста (только для отладки)

```bash
make up SET=dev-min DEBUG=1
PGPASSWORD=$(cat secrets/db_postgres_admin) psql "host=localhost port=15432 user=postgres dbname=postgres sslmode=verify-full sslrootcert=secrets/tls_ca.crt"
```
