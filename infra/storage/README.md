# infra/storage

Объектное хранилище для документов продавцов (паспорта, свидетельства, выписки, FT-2.0). Образ `rustfs/rustfs:1.0.1`, S3 API по TLS. Почему именно он, а не архивный MinIO, Garage или SeaweedFS: [ADR-024](../../docs/05-architecture/adr/ADR-024-object-storage.md).

| Файл | Назначение |
| --- | --- |
| `entrypoint.sh` | Запуск сервера: копирует сертификат и ключ в память под именами `rustfs_cert.pem` и `rustfs_key.pem` (так ждёт сервер, а секреты Docker называются иначе), готовит файлы корневой записи, отключает консоль и передаёт управление штатному сценарию образа |
| `init.sh` | Задание `storage-init` (образ `rustfs/rc:v0.1.36`): бакет `seller-documents`, политика `seller-documents-rw`, учётная запись `catalog-service` с этой политикой. Завершается с кодом 0 |
| `policy-seller-documents.json` | Политика доступа: объекты и многочастная загрузка только в бакете `seller-documents`, список только этого бакета. Всё остальное запрещено |
| `root_user` | Имя корневой записи `dgm-storage-admin` (не секрет). Пароль в секрете `storage_admin` |

## Как это устроено

- **Один порт.** Сервер слушает 9000 по TLS в сети `data`. Консоль управления отключена, на хост порт не публикуется (отладка: `make up SET=dev-platform DEBUG=1` даёт `127.0.0.1:19000`). Сертификат `tls_object-storage` выпускает частный центр сертификации ([ADR-022](../../docs/05-architecture/adr/ADR-022-internal-traffic-encryption.md)), в нём есть имена `object-storage`, `localhost` и `127.0.0.1`.
- **Запуск без root.** Контейнер работает под UID 10001, файловая система только для чтения. Данные в томе `objectdata`, ключи и журнал в `tmpfs`. Лимит памяти 192 МБ, на пике после загрузки файла 12 МБ сервер занимает около 100 МБ.
- **Две учётные записи.** Корневая `dgm-storage-admin` нужна серверу и заданию `storage-init`, сервисы её не получают. Сервис каталога работает под `catalog-service` с паролем из секрета `storage_catalog`: в бакете документов он пишет, читает, перечисляет и удаляет, больше ничего (чужие бакеты, создание и удаление бакетов, настройки недоступны).
- **Подписанные ссылки.** `catalog-service` выдаёт ссылки стандартным S3-клиентом (SigV4, срок 5 минут) для модератора и продавца. Просроченная ссылка и ссылка с испорченной подписью отвергаются, анонимного доступа нет.
- **Пароли только в файлах.** `storage_admin` и `storage_catalog` создаёт `make secrets`, они читаются из `/run/secrets`, в окружение, журнал и вывод `rc` не попадают.

## Инициализация

`storage-init` запускается вместе с хранилищем (`depends_on: service_healthy`) и безопасен при повторе: бакет не пересоздаётся, политика заново записывается из файла, пароль учётной записи ставится заново из секрета. Поэтому смена пароля и правка политики выполняются одинаково:

```bash
# заменить secrets/storage_catalog (или отредактировать policy-seller-documents.json), затем
make storage-init
```

Если сервис каталога уже запущен, ему после смены пароля нужен перезапуск, чтобы пул клиентов получил новый секрет.

## Проверка

```bash
make up SET=dev-platform DEBUG=1     # или любой набор с профилем storage
make storage-check                   # tools/stand-checks/storage_checks.sh, нужен aws CLI v2
```

Проверки (в CI задание `storage`): шифрование и отказ обычному HTTP, ограничения контейнеров, права `catalog-service` в своём и в чужом бакете, подписанные ссылки (рабочая, просроченная, с испорченной подписью), анонимный доступ, повтор init, подмена политики и её возврат, смена пароля (в том числе начинающегося со знака «-»), сохранность данных после перезапуска, пик памяти не выше 85% лимита.

## Подключиться с хоста (только для отладки)

```bash
export AWS_CA_BUNDLE=secrets/tls_ca.crt AWS_DEFAULT_REGION=us-east-1
export AWS_ACCESS_KEY_ID=catalog-service AWS_SECRET_ACCESS_KEY=$(cat secrets/storage_catalog)
aws --endpoint-url https://localhost:19000 s3 ls s3://seller-documents
```

Сервисы обращаются по адресу `https://object-storage:9000` (путевая адресация, регион `us-east-1`), корневой сертификат `tls_ca.crt`.

## Откат на запасной вариант

SeaweedFS 4.48 проходил те же проверки спайка ([ADR-024](../../docs/05-architecture/adr/ADR-024-object-storage.md)). Переход: образ и запуск в `compose.yaml` и `entrypoint.sh`, учётная запись на бакет задаётся файлом идентичностей вместо `rc`, `storage_checks.sh` остаётся тем же.
