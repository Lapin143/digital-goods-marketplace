# infra/kafka

Kafka 4.3 (образ `apache/kafka:4.3.1`) в режиме KRaft: один узел, брокер и контроллер в одном процессе ([ADR-003](../../docs/05-architecture/adr/ADR-003-kafka-events.md)). Темы и права создаёт задание `kafka-init`.

| Файл | Назначение |
| --- | --- |
| `server.properties` | Слушатели `INTERNAL` (9093), `HOST` (19093, отладка с хоста), `CONTROLLER` (9094), SSL и сертификат клиента на всех, принципал из CN, ACL, автосоздание тем выключено |
| `entrypoint.sh` | Склеивает ключ и сертификат в PEM-файл для Kafka, форматирует каталог данных при первом запуске, запускает брокер |
| `gen_kafka.py` | Генератор `topics.sh` из `docs/06-api/asyncapi/asyncapi.yaml`. Режим `--check` сверяет файл с контрактом (входит в `run_all.sh`), режим `--print` показывает таблицу |
| `topics.sh` | Создан генератором, руками не правится: 17 тем и права доступа выпуска R1 |
| `init.sh` | Задание `kafka-init`: ждёт брокер, создаёт недостающие темы и права, ставит метку `dgm-init-<хеш>` |

## Как Kafka узнаёт клиента

Клиент предъявляет сертификат, выпущенный частным центром (`make certs`). Правило `ssl.principal.mapping.rules` берёт из его имени `CN` имя принципала: у сертификата `tls_order-service.crt` принципал `order-service`. Дальше работает список прав (ACL): разрешение записывается как «принципал, операция, ресурс». Всё, что не разрешено, запрещено (`allow.everyone.if.no.acl.found=false`). Суперпользователи: `kafka` (сам брокер) и `kafka-init`.

Права строит `gen_kafka.py` из операций выпуска R1 контракта:

| Кто | Что получает |
| --- | --- |
| Издатель темы (`x-publisher.service`) | `Write` и `Describe` на тему. «Все сервисы» у `audit.events` это шесть прикладных сервисов |
| Потребитель (`x-consumer.service`) | `Read` и `Describe` на тему и `Read` на свою группу (`consumerGroup`) |
| Потребитель с темой недоставленных | `Write` и `Describe` на `<тема>.dlq` |
| Потребитель без группы (`platform.config`) | `Read` на тему, группа не нужна |

Сервис не может писать в чужую тему и читать чужую: проверяет `tools/stand-checks/infra_security.sh`.

## Темы и инициализация

Список тем, число партиций и срок хранения берутся из привязок Kafka в AsyncAPI. Изменили контракт: `make kafka-topics`, затем закоммитьте `topics.sh`. Проверка в CI падает, если файл не совпадает с контрактом. Число партиций у существующей темы `kafka-init` не меняет: это несовместимое изменение ([conventions.md](../../docs/05-architecture/conventions.md), раздел 11.4).

Повторный запуск `kafka-init` занимает секунды: он видит тему-метку с тем же хешем спецификации и ничего не делает. Первый запуск создаёт темы и права отдельными вызовами инструментов Kafka (каждый это JVM), поэтому длится около минуты.

## Отладка с хоста

```bash
make up SET=dev-min DEBUG=1       # порт 19093 на 127.0.0.1
```

Клиент подключается к `localhost:19093` по SSL с сертификатом нужного сервиса (`secrets/tls_<сервис>.key` и `.crt`, склеенные в один PEM-файл) и корневым `secrets/tls_ca.crt`.
