| Поле | Содержание |

## 1. Что получится

Зритель видит весь путь товара от заявки до витрины в настоящем браузере:

1. Покупатель подаёт заявку продавца с документом.
2. Модератор в рабочем месте открывает заявку, смотрит документ и одобряет её.
3. Новый продавец входит с одноразовым кодом (TOTP), заводит товар и отправляет его на модерацию.
4. Модератор публикует товар.
5. Продавец загружает ключи списком и видит остаток, дубликаты отклоняются с причиной.
6. Гость находит товар на витрине, карточка показывает цену и «В наличии».

Ключи в интерфейсе нигде не показываются: ни продавцу после загрузки, ни модератору (INV-20, NFT-3.2). Это стоит сказать вслух при показе.

## 2. Подготовка (один раз, около 10 минут)

| Шаг | Действие | Заметка |
| --- | --- | --- |
| 1 | В `%UserProfile%\.wslconfig` поставьте `memory=4GB`, выполните `wsl --shutdown` и откройте Ubuntu | Набор `dev-sellers` по лимитам занимает 3744 МБ, в 3 ГБ он не помещается ([руководство разработчика](developer-guide.md), разделы 2.2 и 4). После показа верните `3GB` |
| 2 | Закройте браузер, IDE и всё, что не нужно, остановите чужие контейнеры | Запас по памяти у стенда небольшой |
| 3 | `git pull`, затем `make reset` | После обновления кода нужны чистые тома (миграции, realm) |
| 4 | `make up SET=dev-sellers DEBUG=1` | Первый запуск собирает образы сервисов, это занимает несколько минут. `DEBUG=1` нужен для следующей команды и для `make otp` |
| 5 | `make keycloak-users` | Создаёт `buyer-1…3`, `moderator-1…2` и других. Пароли и секреты TOTP лежат в `secrets/test_users.json` |
| 6 | Доверьте корневой сертификат в браузере | [Руководство разработчика](developer-guide.md), раздел 6. Без этого браузер покажет предупреждение на `https://localhost:8443` |
| 7 | Проверьте стенд: `make stand-check SET=dev-sellers DEBUG=1` | Все контейнеры должны быть готовы |

Пароль нужного пользователя:

```bash
python3 -c "import json;print([u['password'] for u in json.load(open('secrets/test_users.json'))['users'] if u['name']=='buyer-2'][0])"
```

Код второго фактора модератора (меняется каждые 30 секунд): `make otp WHO=moderator-1`.

Нужны два изолированных сеанса браузера: один для покупателя (потом продавца), второй для модератора. Подойдут два профиля браузера или обычное окно плюс окно другого профиля; окна «Инкогнито» одного профиля делят один сеанс, и входы будут мешать друг другу. Гость это любая вкладка, где никто не вошёл (например, чистый профиль).

## 3. Сценарий по экранам

Адрес стенда: `https://localhost:8443`. Тексты кнопок ниже взяты из словаря интерфейса ([ru.json](../../frontend/web-app/src/i18n/ru.json)).

### 3.1. Пустая витрина (гость, 1 минута)

1. Откройте `/products` (пункт «Каталог»). Витрина пуста: «В каталоге пока нет товаров.»
2. Скажите: сейчас продавцов нет, их заведёт заявка.

### 3.2. Заявка продавца (покупатель `buyer-2`, 3 минуты)

1. «Войти», логин `buyer-2`, пароль из `secrets/test_users.json`. Код не нужен: у покупателя второго фактора нет.
2. Пункт «Заявка продавца» (`/apply`). Статус «Черновик».
3. Заполните анкету. Подойдут такие значения:

   | Поле | Значение |
   | --- | --- |
   | Тип продавца | Самозанятый |
   | Наименование | Демо Студия |
   | Получатель платежа | Иванов Иван Иванович |
   | Банк | Демо-банк |
   | БИК | `044525225` (9 цифр) |
   | Расчётный счёт | `40817810000000000001` (20 цифр) |
   | Что вы собираетесь продавать | Ключи для инди-игр в Steam |

4. «Добавить документ»: любой небольшой PDF, JPEG или PNG до 2 МБ (например, скриншот). Появится «Документ загружен.»
5. «Сохранить черновик», затем «Отправить на проверку». Сообщение «Заявка отправлена на проверку.», статус «Заявка на проверке, срок рассмотрения до …».

Можно показать ошибки полей: БИК из 8 цифр даёт «БИК состоит из 9 цифр.», файл формата GIF даёт «Подходят только файлы PDF, JPEG и PNG.».

### 3.3. Решение модератора (`moderator-1`, 2 минуты)

1. Другое окно браузера. «Для продавцов и сотрудников» (`/work`), вход сотрудника: логин `moderator-1`, пароль, затем код из `make otp WHO=moderator-1`.
2. «Рабочее место сотрудника», «Заявки продавцов». В очереди заявка «Демо Студия».
3. Откройте карточку заявки: анкета, блок «Документы заявки» со ссылкой на файл (ссылка временная, файл только скачивается; «Ссылки на документы действуют ещё …»).
4. «Одобрить», подтверждение «Одобрить заявку? Продавец получит роль «Продавец» и будет входить с одноразовым кодом.» → «Подтвердить». Сообщение «Заявка одобрена.»

Для показа отказа можно заранее подать вторую заявку от `buyer-3` и нажать «Отказать» с причиной: продавец увидит её на экране заявки, новую заявку можно подать через 24 часа.

### 3.4. Первый вход продавца с настройкой TOTP (3 минуты)

После одобрения у `buyer-2` в Keycloak появились роль `seller` и атрибут `seller_id`, роль `buyer` снята. Токен нужно получить заново.

1. В окне покупателя нажмите «Выйти», затем «Для продавцов и сотрудников» и войдите: логин `buyer-2`, тот же пароль.
2. Keycloak потребует настроить приложение-аутентификатор. Под QR-кодом нажмите «Не удаётся отсканировать?» и скопируйте ключ (группы по четыре буквы и цифры).
3. Получите код без телефона: `make otp KEY="ABCD EFGH IJKL …"` (ключ вставьте как есть, регистр и пробелы не важны). Можно и телефоном: отсканируйте QR-код любым приложением-аутентификатором.
4. Введите код на странице настройки. После настройки токен ещё без второго фактора, поэтому интерфейс отправит на повторный вход (находка F4-2, решение Р-45): введите пароль и новый код (`make otp KEY=…`), один и тот же код Keycloak дважды не принимает.
5. Откроется «Кабинет продавца».

Если вместо кабинета появится «Нужен код из приложения»: токен выдан без второго фактора, нажмите «Войти заново с кодом».

### 3.5. Товар (продавец, 2 минуты)

1. «Мои товары»: «Товаров пока нет. Добавьте первый.»
2. «Добавить товар». Заполните:

   | Поле | Значение |
   | --- | --- |
   | Название | Космический курьер |
   | Описание | Демонстрационная игра для показа среза 1 |
   | Тип товара | Ключ игры |
   | Платформа | Steam |
   | Регионы активации | RU, KZ |
   | Цена, ₽ | 1499,50 |

3. «Сохранить». Затем «Отправить на модерацию»: «Товар отправлен на модерацию.» Форма блокируется: «Товар на модерации: править его нельзя до решения.»
4. Если нужно показать ошибку: цена 0 даёт «Цена должна быть больше нуля, например 1499 или 1499,50.»

### 3.6. Публикация (модератор, 1 минута)

1. «Товары на модерации», карточка «Космический курьер».
2. «Опубликовать», подтверждение «Опубликовать товар? Он появится на витрине.» → «Подтвердить». Сообщение «Товар опубликован.»

Отказ показывает кнопка «Отклонить» с причиной: продавец увидит «Товар отклонён. Причина: …» и сможет исправить и отправить заново.

### 3.7. Ключи и остаток (продавец, 2 минуты)

1. «Мои товары»: статус товара «Опубликован». Откройте товар, нажмите «Остаток и ключи».
2. «Остаток»: все счётчики нулевые.
3. «Загрузить списком», вставьте ключи по одному в строке (повторите одну строку, чтобы показать отказ):

   ```
   DEMO1-AAAAA-11111-XXXXX
   DEMO1-BBBBB-22222-XXXXX
   DEMO1-CCCCC-33333-XXXXX
   DEMO1-DDDDD-44444-XXXXX
   DEMO1-EEEEE-55555-XXXXX
   DEMO1-AAAAA-11111-XXXXX
   ```

4. «Загрузить ключи». Ожидаемый итог: «Принято ключей: 5. Отклонено строк: 1. Остаток: 5, предел пула 100000.» В таблице «Отклонённые строки» строка 6 с причиной «Повтор в этой загрузке».
5. Загрузите тот же ключ ещё раз: причина «Уже есть в пуле товара». Поле ввода очищается, ключей на странице нет.
6. «Обновить остаток»: «Свободные ключи (остаток)» равно 5, «В резерве под заказы» и «Выданы покупателям» равны 0.

Остаток из inventory-service доходит до витрины событием через Kafka, поэтому цифра на витрине может появиться через несколько секунд.

### 3.8. Витрина (гость, 1 минута)

1. Окно гостя, `/products`. Введите «Космический» в поле «Название», нажмите «Показать».
2. В списке «Космический курьер» с ценой и пометкой «В наличии». Откройте карточку: «Платформа: Steam», регионы RU и KZ, «В наличии, можно заказать до N шт.» (N не больше числа загруженных ключей).
3. Карточка читается из кэша Redis; «Обновить наличие» запрашивает данные заново.

Заказ и оплата в срез 1 не входят (срез 2).

## 4. Если что-то пошло не так

| Признак | Что проверить |
| --- | --- |
| Браузер ругается на сертификат | Раздел 6 руководства разработчика, корневой сертификат `secrets/tls_ca.crt` |
| Контейнеры падают или стенд тормозит | `memory=4GB` в `.wslconfig`, закрыты ли браузер и IDE, `make stand-check SET=dev-sellers DEBUG=1` |
| «Неверный пароль» при входе | Пароли тестовых пользователей одноразовые, после `make keycloak-users` они новые; смотрите `secrets/test_users.json` |
| Код TOTP не принимается | Код действует 30 секунд и одноразовый: возьмите новый, часы в WSL после сна ноутбука могут отставать, тогда `wsl --shutdown` и новый запуск Ubuntu |
| После одобрения кабинет не открывается | Выйдите и войдите заново через «Для продавцов и сотрудников», роль приходит только в новом токене |
| Товар не виден на витрине | Статус «Опубликован»? Ключи загружены? Подождите несколько секунд, нажмите «Обновить наличие»; журналы `make logs S=catalog-service` и `make logs S=inventory-service` |
| Нужно начать сценарий заново | Другие `buyer-N` или `make reset`, затем шаги 4 и 5 подготовки |

## 5. Что проверяется автоматически

| Команда | Что покрывает из сценария | Где проходит в CI |
| --- | --- | --- |
| `make sellers-check` | Заявка: черновик, документы через шлюз, подача на проверку (раздел 3.2) через API | Задание `e2e` |
| `make seller-approval-check` | Отказ, доработка, одобрение, роль `seller` и `seller_id`, настройка TOTP при первом входе, кабинет только со вторым фактором, товар от подачи до витрины (модерация, кэш, поиск), загрузка ключей и остаток, проверка, что ключи не попадают в журналы, события и дамп базы (разделы 3.3 – 3.8) через API | Задание `e2e` |
| `make ui-smoke` | Вход модератора с TOTP в браузере, очередь заявок, «Одобрить», «Опубликовать», «Отклонить» с причиной, поиск товара гостем и карточка (разделы 3.3, 3.6, 3.8) в настоящем Chromium | Задание `e2e` |
| Vitest и тесты сервисов | Экраны кабинета продавца и ключей, правила цены, регионов и дубликатов | Задания `web`, `services` |

Экраны кабинета продавца (разделы 3.4, 3.5 и 3.7) в настоящем браузере на стенде автоматически не проходят: они проверены модульными тестами и через API. Поэтому первый ручной проход по сценарию нужен, и его результат вносится ниже.

## 7. Запись видео

Две готовые записи делает CI: задание `e2e` пишет экран дымового сценария (модератор входит с TOTP и принимает решения, гость находит товар) в `moderator.webm` и `guest.webm`, файлы лежат в артефакте запуска `ui-smoke-report`, папка `video`. Запись кабинета продавца сделайте сами:

Запишите экран целиком, три окна браузера в раскладке «плитка». Подходящий порядок кадров: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8. Сжатое видео или GIF положите в каталог `docs/assets/demo/` и добавьте ссылку в [README.md](../../README.md), раздел «Демо». Не показывайте на записи файл `secrets/test_users.json` и значения реальных паролей.
