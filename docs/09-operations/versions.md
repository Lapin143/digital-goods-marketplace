Документ отвечает на вопросы «какая версия чего используется и почему именно она» и «когда и как её менять». Версии нигде, кроме этого документа, `gradle/libs.versions.toml` и `compose.yaml`, не повторяются. Если версия изменилась, правится таблица и файл, который её использует, одним commit.

## 1. Правила

| № | Правило | Как применяется |
| --- | --- | --- |
| 1 | Только поддерживаемые версии | Версия выбирается из линейки, которую разработчик ещё исправляет. Дата конца поддержки записана в таблице. Версия, у которой конец поддержки раньше срока проекта (конец 2027 года), не берётся |
| 2 | LTS там, где он есть | Java и Node берутся из линейки с долгой поддержкой (Java 25, Node 24). Предварительные выпуски, релиз-кандидаты и ветки `main` не используются |
| 3 | Точный номер, а не «latest» | В `compose.yaml` образы указаны полным номером версии. Исключение одно: базовый образ Java (раздел 4), потому что исправления безопасности должны приходить без правки кода |
| 4 | Одна точка правды для зависимостей Gradle | Версии библиотек лежат в `gradle/libs.versions.toml`. Библиотеки Spring получают версии из BOM, явно задаются только те, которых в BOM нет |
| 5 | Обновления идут по расписанию | Dependabot проверяет Gradle, Docker и GitHub Actions раз в неделю, исправления безопасности применяются вне очереди. Обновление проходит те же проверки CI, что обычный commit |
| 6 | Непроверенная версия не выпускается | Образ, которого нет в реестре на момент проверки, в таблицу не попадает. Находка записывается в решения этого документа |

## 4. Базовый образ Java и образы сервисов

Базовый образ `eclipse-temurin:25-jre-noble` указывается без номера исправления. Причина: Temurin публикует исправления безопасности JDK в той же линейке 25, и сервисы должны получать их при каждой пересборке, не меняя код. Воспроизводимость обеспечивается так: дайджест базового образа записывается в метку `org.opencontainers.image.base.digest` каждого собранного образа, Trivy сканирует образы при каждой сборке в CI (ST-14).

Образы сервисов запускаются от пользователя без прав (UID 10001), с файловой системой только для чтения и временным каталогом в памяти. Подробности в [ADR-023](../05-architecture/adr/ADR-023-build-and-stack.md).

## 5. Что не выбрано и почему

| Вариант | Почему не взят |
| --- | --- |
| Spring Boot 4.0.x | Поддерживается меньше, чем 4.1, у Spring Cloud та же совместимость |
| Spring Cloud 2026.0 | Только предварительные выпуски, для основы проекта не подходят |
| Java 21 | Старая линейка LTS, поддерживается дольше срока проекта, но Java 25 даёт тот же уровень поддержки Spring Boot и дольше живёт |
| Java 26 | Не LTS, поддержка полгода |
| Kafka 4.4 | Релиз-кандидаты, стабильного выпуска нет |
| Redis 8.10 | Основная линейка, исправления выходят чаще, но поддержка короче. Выбрана линейка 8.2 с долгой поддержкой |
| Valkey вместо Redis | Совместимая замена с лицензией BSD. Рассматривается, если лицензия Redis станет препятствием (AGPLv3 для неизменённого образа не мешает). Клиентский код не меняется |
| Tempo 3.0 | Новая архитектура приёма данных на основе очереди (Kafka), для одного узла избыточна, одноузловой режим 3.x не проверялся. Версия 2.10 поддерживается и достаточна для NFT-6.0 |
| Prometheus LTS-линейка | Версия 3.14 текущая и поддерживается, срок проекта короче срока поддержки |
| Образы Alpine для PostgreSQL | Другая библиотека локалей (musl), сортировка строк отличается от проверенной в Ф2 |

## 6. Инструменты CI

Версии действий GitHub Actions закрепляются по хешу коммита в шаге 17. До этого используются теги основных версий (`@v4`, `@v5`), и это известный риск цепочки поставок, который закрывается там же.

| Инструмент | Назначение | Как закрепляется |
| --- | --- | --- |
| `actions/checkout`, `actions/setup-java`, `actions/upload-artifact` | Базовые шаги | Хеш коммита, шаг 17 |
| `gradle/actions/setup-gradle` | Кэш и проверка wrapper | Хеш коммита, шаг 17 |
| `docker/login-action`, `docker/build-push-action` | Публикация образов | Хеш коммита, шаг 17 |
| Gitleaks | Поиск секретов, ST-14 | Версия бинарного файла в задании `security` |
| Trivy | Уязвимости зависимостей и образов, ST-14 | Версия бинарного файла в задании `security` |
| Раннер `ubuntu-24.04` | Среда CI | Метка в workflow. Фактические параметры (4 ядра, 16 ГБ, Docker 28, Compose 2.38) проверены 4 октября 2026 года |

## 7. Решения и замечания

| № | Вопрос | Решение | Причина |
| --- | --- | --- | --- |
| 1 | Как закрыть вопрос D-4 | Версии зафиксированы в этом документе, проверка при каждом изменении | Вопрос о версиях был отложен до Ф3, чтобы взять актуальные на момент кода, а не на момент проектирования |
| 2 | Spring Cloud и Spring Boot | Обе линейки взяты текущими и взаимно совместимыми | Совместимость проверена по документации Spring (раздел 2) |
| 3 | Версия Gradle | 9.8.0 | Текущая стабильная, совместима со Spring Boot 4.1 и Java 25 |
| 4 | Образ Keycloak | Тег `26.8.0` с `quay.io` | Реестр `quay.io` недоступен из рабочей среды, существование тега подтверждает задание `images` в CI |
| 5 | Объектное хранилище | Не выбрано в этом шаге | MinIO больше не развивается, замена выбирается спайком в шаге 8 (ADR-024) |
| 6 | Образы `backup-job` и `certbot` | Выбираются в Ф6 | Профиль `ops` не входит в наборы Ф3 |
