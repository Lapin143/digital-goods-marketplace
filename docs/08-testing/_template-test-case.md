# Шаблон тест-кейса

Файл тест-кейсов области (`TC-*.md`) состоит из шапки, раздела «Как читать», сводной таблицы (TC, Название, История, Уровень, Чем проверяется) и самих тест-кейсов. Каждый тест-кейс оформляется так (образец: [TC-accounts.md](TC-accounts.md)); скрипт `tools/docs-checks/check_testcases.py` проверяет файл и сверяет его с кодом.

### TC-NNN. Название проверки

| Поле | Содержание |
| --- | --- |
| ID | TC-NNN |
| User story | US-X.Y (сценарий N) |
| Требования | FT-..., NFT-... |
| Уровень | L1 – L8 ([test-strategy.md](test-strategy.md), раздел 2) |
| Тип | UI / API / интеграционный / конкуренция / нагрузочный / безопасность / эксплуатационный |
| Приоритет | Высокий / Средний / Низкий |
| Автоматизация | Ручной / JUnit / JUnit на стенде / Vitest / Newman / Python на стенде / k6 (если проверок несколько, через точку с запятой) |
| Тег в коде | TC-NNN |
| Где в коде | `путь/к/файлу` через запятую; у ручного теста прочерк |

**Предусловия.** Данные и состояние системы до начала проверки.

**Шаги.**

1. ...
2. ...

**Ожидаемый результат.** Что должно произойти. Если проверка касается сроков, указано пороговое значение.

Номер `TC-NNN` стоит и в коде: `@Tag("TC-NNN")` у метода JUnit, имя проверки в скрипте стенда, заголовок шага сценария Newman, `(TC-NNN)` в названии `describe` у теста Vitest. Файл с автоматизацией, в котором есть номер, но которого нет в поле «Где в коде», считается ошибкой, как и наоборот.

Если файл области содержит раздел «Резерв номеров» (таблица с колонками «Номера» и «Сценарии»), перечисленные в нём номера можно пропускать в нумерации: они закреплены за проверками следующих шагов. Номер из резерва не должен быть описан тест-кейсом.
