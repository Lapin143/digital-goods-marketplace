# Ф0. Подготовка окружения: пошаговая инструкция

**Для кого:** Windows 11 Home, 8 ГБ оперативной памяти, опыта с GitHub и Docker нет.
**Время:** 2–4 часа вместе с перезагрузками.
**Результат:** веха M0. Репозиторий на GitHub, рабочие WSL2 и Docker, редактор.

Идите по шагам сверху вниз. Если что-то не получилось, остановитесь на этом шаге и разберите проблему по таблице в конце документа. Дальше идти не нужно.

**Где вводить команды.** В инструкции два терминала. Команды `wsl ...` и `docker ...` вводятся в **PowerShell** (строка начинается с `PS C:\...>`). Команды Linux вроде `free -h` вводятся в **Ubuntu** (строка вида `имя@компьютер:~$`). Если команда выдаёт `command not found`, проверьте, в том ли терминале вы находитесь.

---

## Шаг 1. Проверяем компьютер

**1.1. Виртуализация.** Без неё WSL2 и Docker не запустятся.

1. Нажмите `Ctrl + Shift + Esc`, откроется Диспетчер задач.
2. Если окно маленькое, нажмите «Подробнее».
3. Вкладка «Производительность» → «ЦП».
4. Внизу справа найдите строку **«Виртуализация»**. Должно быть **«Включено»**.

Если написано «Отключено», её нужно включить в BIOS:

1. Перезагрузите компьютер и при включении несколько раз нажимайте клавишу входа в BIOS. У разных производителей она разная: чаще всего `Del`, `F2`, `F10` или `Esc`.
2. Найдите параметр с названием **Intel Virtualization Technology** (или VT-x) для процессоров Intel, либо **SVM Mode** для AMD. Обычно он в разделах Advanced или CPU Configuration.
3. Переключите на **Enabled**, сохраните настройки (обычно `F10`) и перезагрузитесь.

Если не нашли параметр, найдите инструкцию для вашей модели компьютера: название и расположение настройки у производителей отличаются.

**1.2. Место на диске.** Откройте «Этот компьютер» и посмотрите свободное место на диске C:. Нужно **не менее 40 ГБ**.

**1.3. Обновления.** Параметры → Центр обновления Windows → «Проверить наличие обновлений». Установите всё, что предложит, и перезагрузитесь.

## Шаг 2. Аккаунт GitHub

1. Откройте https://github.com и нажмите **Sign up**.
2. Выберите имя пользователя аккуратно: оно будет в ссылке, которую вы покажете работодателю. Лучше всего подходят имя и фамилия латиницей (например, `ivan-petrov`) без цифр и шуток.
3. Подтвердите почту кодом из письма.
4. Включите двухфакторную защиту: аватар справа вверху → **Settings** → **Password and authentication** → **Two-factor authentication**. Удобнее всего приложение-аутентификатор на телефоне. **Сохраните коды восстановления** в надёжном месте: без них при потере телефона вы потеряете доступ.

---

## Шаг 3. GitHub Desktop

1. Скачайте программу с https://desktop.github.com и установите.
2. При первом запуске нажмите **Sign in to GitHub.com**, войдите через браузер и разрешите доступ.
3. На шаге настройки Git укажите имя и адрес почты. Репозиторий будет публичным, поэтому, если программа предлагает **адрес вида `...@users.noreply.github.com`** (скрытая личная почта), выбирайте его: так ваша настоящая почта не попадёт в историю изменений. Настройки можно поменять позже в меню File → Options → Git.

## Шаг 4. Создаём репозиторий

1. На сайте github.com нажмите **+** справа вверху → **New repository**.
2. Заполните:
   - **Repository name:** `digital-goods-marketplace`
   - **Description:** `Маркетплейс цифровых товаров: микросервисы, документация, демо`
   - **Public** (публичный)
   - Поставьте галочку **Add a README file**
   - **Add .gitignore:** оставьте `None` (добавим позже)
   - **Choose a license:** `MIT License`
3. Нажмите **Create repository**.

---

## Шаг 5. Копируем репозиторий на компьютер

**Сначала создайте папку для проектов.** Откройте проводник, зайдите на диск C: и создайте папку `dev` (получится `C:\dev`).

Почему не «Документы» и не «Рабочий стол»: Windows часто синхронизирует эти папки с OneDrive, а это ломает Git и Docker. Кириллица и пробелы в пути тоже вызывают сюрпризы у инструментов разработки.

Теперь в GitHub Desktop:

1. **File → Clone repository**.
2. Вкладка **GitHub.com**, выберите `digital-goods-marketplace`.
3. В поле **Local path** укажите `C:\dev\digital-goods-marketplace`.
4. Нажмите **Clone**.

---

## Шаг 6. Первый commit и push

Это базовый цикл работы с Git. Он будет повторяться на каждом этапе проекта.

1. Откройте папку `C:\dev\digital-goods-marketplace` в проводнике.
2. Откройте файл `README.md` в Блокноте, допишите строку: `Учебный проект: маркетплейс цифровых товаров.` Сохраните.
3. Вернитесь в GitHub Desktop. Слева появится изменённый файл.
4. Внизу слева в поле **Summary** напишите: `docs: первая правка README`.
5. Нажмите **Commit to main**. Изменение сохранено на вашем компьютере.
6. Нажмите **Push origin** (кнопка вверху). Изменение отправлено на GitHub.
7. Откройте страницу репозитория на github.com и обновите её. Вы увидите новую строку в README.

**Запомните:** commit сохраняет версию у вас, push отправляет её на GitHub.

## Шаг 7. WSL2 (Linux внутри Windows)

Docker использует WSL2, поэтому ставим его первым.

1. Нажмите кнопку «Пуск», напишите `PowerShell`, правой кнопкой по «Windows PowerShell» → **Запуск от имени администратора**.
2. Введите команду и нажмите Enter:

```
wsl --install
```

3. Дождитесь окончания и **перезагрузите компьютер**.
4. После перезагрузки автоматически откроется окно Ubuntu. Подождите окончания установки, затем придумайте **имя пользователя** (латиница, строчными) и **пароль**. Пароль при вводе на экране не отображается, это нормально. Запишите его.
5. Проверьте версию. В обычном PowerShell выполните:

```
wsl -l -v
```

В колонке VERSION должна быть цифра **2**.

Если появилось сообщение про необходимость обновить ядро, выполните `wsl --update`. Если сообщение про отключённую виртуализацию, вернитесь к шагу 1.1.

## Шаг 8. Ограничиваем память WSL2

Без ограничения WSL2 может занять большую часть из 8 ГБ, и Windows начнёт тормозить. После перезагрузки Windows без нагрузки занимает около 4–5 ГБ, поэтому WSL2 получает 3 ГБ, а нехватку покрывает файл подкачки (swap) на диске.

1. Нажмите `Win + R`, введите `%UserProfile%` и нажмите Enter. Откроется ваша пользовательская папка.
2. Создайте в ней файл с именем **`.wslconfig`** (с точкой в начале, без расширения). Проще всего: правая кнопка → Создать → Текстовый документ, затем переименовать. Если Windows добавила `.txt`, включите показ расширений (проводник → Вид → Показать → Расширения имён файлов) и уберите его.
3. Откройте файл в Блокноте и вставьте:

```
[wsl2]
memory=3GB
swap=4GB
```

4. Сохраните. В PowerShell выполните:

```
wsl --shutdown
```

Настройка применится при следующем запуске WSL.

5. Проверьте. В PowerShell выполните `wsl -d Ubuntu`, затем в окне Ubuntu:

```
free -h
```

В строке `Mem` в колонке `total` должно быть около **2.8Gi**, в строке `Swap` **4.0Gi**. Если видите около 7Gi, файл назван неверно (например, `.wslconfig.txt`) или не был выполнен `wsl --shutdown`. Выйдите из Ubuntu командой `exit`.

## Шаг 9. Docker Desktop

1. Скачайте Docker Desktop для Windows с https://www.docker.com/products/docker-desktop и установите. Для личного использования программа бесплатна.
2. Если установщик спросит про бэкенд, оставьте галочку **Use WSL 2 instead of Hyper-V**.
3. Перезагрузите компьютер, запустите Docker Desktop и примите соглашение. Регистрироваться в Docker необязательно, можно пропустить.
4. Откройте настройки (шестерёнка) → General и **снимите галочку «Start Docker Desktop when you sign in to your computer»**. Так Docker не будет занимать память, пока он не нужен.
5. Проверьте. В PowerShell выполните:

```
docker version
docker run hello-world
```

Во втором случае среди текста должна появиться фраза **«Hello from Docker!»**. Это значит, что Docker работает.

## Шаг 10. VS Code

1. Скачайте с https://code.visualstudio.com и установите. В установщике отметьте пункты **«Добавить в PATH»** и **«Открывать с помощью Code»** (для папок).
2. Откройте VS Code → слева значок расширений (квадратики). Найдите через поиск и установите:
   - **Markdown Preview Mermaid Support** (рисует диаграммы Mermaid в просмотре Markdown)
   - **Markdown All in One**
   - **YAML**
   - **Docker**
   - **WSL**
3. **File → Open Folder** и выберите `C:\dev\digital-goods-marketplace`.
4. Откройте `README.md` и нажмите `Ctrl + Shift + V`: появится окно предпросмотра.

**JDK и Java пока не ставим.** Сборка проекта будет идти внутри Docker, поэтому Java на вашем компьютере не понадобится. Вернёмся к этому в Ф3, если появится причина.

## Если что-то пошло не так

| Проблема | Что делать |
| --- | --- |
| Ошибка `0x80370102` или сообщение, что виртуальная машина не может запуститься | Виртуализация выключена в BIOS. Вернитесь к шагу 1.1 |
| «WSL 2 requires an update to its kernel component» | В PowerShell выполните `wsl --update`, затем `wsl --shutdown` |
| Docker Desktop долго пишет «Starting» | Закройте Docker Desktop, выполните `wsl --shutdown`, запустите Docker снова. Если не помогло, перезагрузите компьютер |
| GitHub Desktop не может отправить изменения (ошибка авторизации) | File → Options → Accounts: выйдите и войдите заново через браузер |
| Команда `wsl --install` не найдена или не работает | Обновите Windows (шаг 1.3) и повторите. Проверьте, что PowerShell запущен от имени администратора |
| Сообщение «Конфигурация прокси-сервера localhost обнаружена, но не отражена в WSL» | Безвредное предупреждение WSL. Если пропадёт сеть в Ubuntu или Docker, отключите прокси-клиент на время проверки |
| В Ubuntu не принимается пароль при `sudo` | Пароль вводится вслепую, проверьте раскладку (английская). Сброс: в PowerShell `wsl -d Ubuntu -u root`, затем `passwd ИМЯ_ПОЛЬЗОВАТЕЛЯ` и `exit` |
| В VS Code «Error while fetching extensions. Failed to fetch» | Перезапустите VS Code, проверьте, открывается ли marketplace.visualstudio.com в браузере, попробуйте включить или выключить прокси-клиент. Расширения не блокируют работу, их можно поставить позже |
| Windows сильно тормозит при запущенном Docker | Это ожидаемо на 8 ГБ. Закройте браузер и лишние программы, а Docker Desktop завершайте, когда он не нужен (правая кнопка по значку в трее → Quit). Лимиты подберём замером в Ф3 |
