## Как читать

1. Начните с [bounded-contexts.md](bounded-contexts.md): какие есть контексты и как они общаются.
2. Затем [domain-model.md](domain-model.md): что лежит внутри каждого контекста и какие правила нельзя нарушить.
3. ER-диаграмма [logical-er.md](logical-er.md) собирает те же сущности в одну картину со связями.

## Правила, по которым собраны документы

- У каждой сущности один контекст-владелец. Если сущность меняют два контекста, границы проведены неверно, и такое место решается командой или событием владельцу.
- Между контекстами сущности связаны только по идентификатору. На ER-диаграмме это пунктирные линии, сплошные линии идут только внутри контекста.
- Статусы взяты из статусных моделей SM-01 … SM-11 и не переопределяются.
- Инварианты имеют номера INV-NN. Они используются в тест-кейсах Ф4 и в проверках шага 7.
- Атрибуты, добавленные при проработке процессов и отсутствующие в разделе 6.1 требований, помечены в карточках сущностей. Версия 1.6 требований внесла их в раздел 6.1.
