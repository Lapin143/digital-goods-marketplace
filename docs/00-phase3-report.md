## 1. Итог

Фаза Ф3 завершена: из репозитория одной командой `make up SET=full-obs` поднимается весь каркас релиза R1: 22 контейнера, из них 16 в наборе `full` (PostgreSQL, Redis и Kafka с TLS и правами доступа, объектное хранилище, заглушки внешних систем, Keycloak с realm как кодом, шлюз, веб-интерфейс (заглушка) и шесть сервисов на Java) и 6 стека наблюдения. Настоящий токен Keycloak проходит через шлюз до сервиса и возвращает данные, запрос без токена получает 401, а сервис не принимает соединение без клиентского сертификата. На `main` зелёный запуск CI из 16 заданий, образы сервисов публикуются в реестр GHCR.

Что значит «каркас». Код сервисов в нём пока почти пустой (три операции «ходячего скелета»), зато всё, на чём этот код будет стоять, уже работает и проверено: сертификаты и секреты, базы с миграциями и ролями, события через Outbox, проверка токенов, ограничение частоты, правила модульности, журналы, метрики, трассировка, сборка, образы, сканирование безопасности и замеры памяти. Срез 1 в Ф4 начинается с бизнес-логики, а не с инфраструктуры.

## 3. Принятые решения

| Решение | Суть | Почему так |
| --- | --- | --- |
| Версии (D-4) | Java 25 LTS, Spring Boot 4.1.1, Gradle 9.8.0, образы с точным тегом. Нижние границы Tomcat 11.0.25 и Jackson 3.1.7 (с 6 октября 2026 года 3.2.3) заданы в каталоге версий | BOM Spring Boot 4.1.1 приносит Tomcat 11.0.24 (CVE-2026-65182, CRITICAL) и Jackson 3.1.5 (пять HIGH). Trivy блокирует образ с такой дырой, поэтому границы подняты, а не исключения |
| Gradle, а не Maven | Kotlin DSL, `build-logic`, каталог версий, `-Werror`, один wrapper | В документах Ф2 сборщик назван по-разному ([ADR-023](05-architecture/adr/ADR-023-build-and-stack.md)). Gradle даёт кэш сборки и каталог версий как одну точку правды, общая логика сборки лежит в `build-logic` |
| Код проверяет GitHub Actions | Песочница не запускает Docker и не достаёт Maven Central, поэтому компиляция, тесты и стенд проверяются только в CI, причина красного запуска читается из аннотаций | Единственный надёжный судья тут CI. Контроли сами проверяются самопроверками (`tools/ci/selftest.sh`): проверка, которая ни разу не сработала, ничего не гарантирует |
| RustFS вместо MinIO | Один контейнер `object-storage` с тем же S3 API | MinIO архивирован в апреле 2026. Три кандидата сравнены спайком на раннере CI, запасной вариант SeaweedFS 4.48 ([ADR-024](05-architecture/adr/ADR-024-object-storage.md)) |
| Интеграционные тесты на стенде | Тесты L3 подключаются к поднятому `dev-min` по отладочным портам, а не к Testcontainers | На стенде уже настроены TLS, права Kafka по CN и роли баз, то есть тест идёт теми же путями, что сервис. Решение 11 [стратегии тестирования](08-testing/test-strategy.md) |
| Секреты только файлами | Переменные окружения с именами `*PASSWORD*`, `*SECRET*`, `*TOKEN*`, `*_KEY` обязаны оканчиваться на `_FILE`, проверяет `check_compose.py` | Пароль в окружении виден в `docker inspect` и журналах |
| Миграции делает сервис | Flyway из Spring Boot при старте под ролью-мигратором, затем пулы открываются под рабочими ролями модулей. Образ Flyway CLI используется только в проверках стенда и для `make db-migrate` | У каждого сервиса своя схема, отдельного задания миграций в Compose нет. CLI и библиотека применяют одни и те же файлы: задание `kit` применяет их CLI и затем запускает сервис, который принимает такую базу |
| Тестовые данные в профиле | Профиль Spring `testdata` добавляет миграцию 1000 (три товара, четыре заказа), продуктовый код их не знает | Ходячему скелету нужны данные, а в продуктовой миграции им не место. Проверка миграций пропускает эти данные, если профиль выключен (раздел 5.1, F3-12) |
| Наборы Compose | Семь наборов от `dev-min` до `server`, в каждом лимиты по таблице бюджета | Ноутбук ограничен 3 ГБ для WSL ([developer-guide.md](09-operations/developer-guide.md), раздел 4) |
| Правило памяти | Пик не выше 85 % лимита, лимит сервиса на Java равен куче плюс 160 МБ. Keycloak и Kafka в формулу не входят, их лимиты подобраны по замеру | Замеры `docker stats` каждые 3 с по шести запускам CI. Шлюз вырос с 320 до 352 МБ (куча 192 МБ) после пика 86 % |
| Шлюз «тонкий» | Проверка токена, области, лимиты, размер тела. Бизнес-правил нет. При недоступном Redis запросы идут, метрика растёт | [ADR-021](05-architecture/adr/ADR-021-api-gateway.md). Доступность важнее точности лимита, критичные лимиты (коды, SMS) живут в `platform-service` |
| Наблюдение | Prometheus опрашивает сервисы по mTLS, Alloy принимает OTLP только с клиентским сертификатом | Те же правила доверия, что у остальной сети |
| Отладочный файл | `compose.debug.yaml` публикует порты только на 127.0.0.1 и не входит в наборы сервера | Сеть `data` закрыта для выхода, порты нужны только разработчику |

## 5. Находки и замечания

| № | Находка | Что сделано |
