# Проверки документов и контрактов

Документы проекта пишутся как код, поэтому их проверяют скриптами: так нельзя выпустить битую ссылку, несуществующий идентификатор требования, контракт, который не проходит собственные примеры, или таблицу, которая расходится с моделью. Все скрипты читают репозиторий и ничего в нём не меняют, кроме явно названных режимов записи.

## Запуск

Из корня репозитория:

```bash
bash tools/docs-checks/run_all.sh          # документы, истории, use cases, архитектура, AsyncAPI, OpenAPI
bash tools/docs-checks/run_all.sh --db     # то же плюс физическая модель на PostgreSQL 16
```

Код выхода 0 означает, что проблем нет. Требования: Python 3 с PyYAML и jsonschema, для диаграмм Mermaid CLI `mmdc` (пакет `@mermaid-js/mermaid-cli`), для проверок БД PostgreSQL 16.

## Проверки БД

Скрипты в `db/` подключаются к PostgreSQL на сокете `/tmp`, порт 5433, пользователь `postgres`, доверительная аутентификация. Пример запуска пустого экземпляра для проверок (без установки пакетов в систему, под обычным пользователем):

```bash
D=/tmp/pg16data
initdb -D $D -U postgres --auth=trust -E UTF8
pg_ctl -D $D -o "-p 5433 -k /tmp -c listen_addresses= -c fsync=off" -l /tmp/pg16.log -w start
```

Драйверы Python не нужны: `db/pgmini.py` реализует минимальный клиент на стандартной библиотеке, потому что тестам конкуренции нужны настоящие параллельные сессии.

## CI и Ф3

С Ф3 `run_all.sh --db` запускается в CI (задание `docs`, [tools/ci/README.md](../ci/README.md)): PostgreSQL 16 и Mermaid CLI ставятся на раннере. В конце вывода `run_all.sh` печатает сводку ошибок, поэтому причина падения видна и в аннотации CI. Скрипты Ф3 `check_compose.py` (Compose против c4-deployment и memory-budget) и `check_realm.py` (realm Keycloak против roles-permissions) добавляются в `run_all.sh` в своих шагах. Промышленные инструменты (Spectral для OpenAPI, AsyncAPI CLI, Flyway и Testcontainers для миграций) подключаются к CI по мере появления кода.
