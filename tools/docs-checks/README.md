# Проверки документов и контрактов

Документы проекта пишутся как код, поэтому их проверяют скриптами: так нельзя выпустить битую ссылку, несуществующий идентификатор требования, контракт, который не проходит собственные примеры, или таблицу, которая расходится с моделью. Все скрипты читают репозиторий и ничего в нём не меняют, кроме явно названных режимов записи.

## Запуск

Из корня репозитория:

```bash
bash tools/docs-checks/run_all.sh          # документы, истории, use cases, AsyncAPI, OpenAPI
bash tools/docs-checks/run_all.sh --db     # то же плюс физическая модель на PostgreSQL 16
```

Код выхода 0 означает, что проблем нет. Требования: Python 3 с PyYAML и jsonschema, для диаграмм Mermaid CLI `mmdc` (пакет `@mermaid-js/mermaid-cli`), для проверок БД PostgreSQL 16.

## Что проверяет каждый скрипт

| Скрипт | Что проверяет |
| --- | --- |
| `validate_docs.py` | Стиль (без длинного тире, без CR и пробелов в конце строк, без маркеров недописанного текста), существование FT, NFT и BG из требований, относительные ссылки, число колонок в таблицах, отрисовку каждого блока Mermaid через `mmdc` |
| `check_us.py` | Истории: формат «Как…, я хочу…, чтобы…», сценарии Дано, Когда, Тогда, ссылки на процессы, статусные модели и требования, покрытие FT историями |
| `check_uc.py` | Use cases: поля шапки, разделы, ссылки на BPMN и SM, симметрия с историями |
| `check_asyncapi.py` | Контракт событий: структура AsyncAPI 3.0, схемы и примеры, темы и ключи против ADR-003 и conventions.md, потребители и ключи идемпотентности, сверка с bounded-contexts.md и c4-components.md. Режим `--write-catalog` пересобирает каталог событий в `docs/06-api/events/README.md` |
| `check_openapi.py` | Контракты REST: структура, `$ref`, ошибки по реестру проблем, безопасность против матрицы прав, идемпотентность и версии, примеры по JSON Schema 2020-12, соглашения об именах, покрытие историй, актуальность каталога. Режим `--write-catalog` пересобирает каталог операций в `docs/06-api/openapi/README.md` |
| `db/` | Прогон DDL с нуля на PostgreSQL 16 (`apply.sh`), 39 тестов инвариантов и гонок (`test_db.py`), сверка столбцов с доменной моделью (`check_datamodel.py`), планы 113 запросов через `EXPLAIN` (`check_explain.py`) |

## Проверки БД

Скрипты в `db/` подключаются к PostgreSQL на сокете `/tmp`, порт 5433, пользователь `postgres`, доверительная аутентификация. Пример запуска пустого экземпляра для проверок (без установки пакетов в систему, под обычным пользователем):

```bash
D=/tmp/pg16data
initdb -D $D -U postgres --auth=trust -E UTF8
pg_ctl -D $D -o "-p 5433 -k /tmp -c listen_addresses= -c fsync=off" -l /tmp/pg16.log -w start
```

Драйверы Python не нужны: `db/pgmini.py` реализует минимальный клиент на стандартной библиотеке, потому что тестам конкуренции нужны настоящие параллельные сессии.
