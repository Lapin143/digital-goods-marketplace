# tools/ops

Инструменты оператора, которые нужны не стенду, а эксплуатации: ими пользуются по [runbook](../../docs/09-operations/runbook.md).

| Файл | Что делает |
| --- | --- |
| `dlq_replay.py` | Очередь недоставленных сообщений: `list` (что лежит в `<тема>.dlq`), `show` (одна запись без значений), `replay` (вернуть запись в исходную тему, без `--yes` только показать). Работает через контейнер Kafka в сети стенда, нужен только Docker и Python. Порядок разбора и случаи, когда события возвращать нельзя: runbook, раздел 4.1 «Событие в `.dlq`» |
| `test_dlq_replay.py` | Модульные тесты скрипта без Docker: разбор вывода консоли Kafka, выбор записи по событию и по месту, строка возврата, защита от слепого возврата, проверка текста обоих скриптов командой `bash -n`. Запуск: `python3 -m unittest tools/ops/test_dlq_replay.py` (входит в `tools/docs-checks/run_all.sh`) |
| `kek_rotate.py` | Ротация мастер-ключа ключей товаров (`inventory_kek`, ADR-009): `status` (где ротация, сколько DEK на какой версии), `start` (создать `inventory_kek_next`, перезапустить `inventory-service` с двумя мастер-ключами, дождаться перезаворачивания DEK), `finish` (сделать следующий ключ текущим, прежний убрать в `secrets/archive`). Без `--yes` только показывает план, `finish` не делает ничего, пока на прежней версии остаётся хоть один DEK, значения ключей не печатает. Порядок и разбор сбоев: runbook, раздел 3.5. Нужны Docker и Python |
| `test_kek_rotate.py` | Модульные тесты скрипта без Docker: разбор `.env`, оценка состояния ротации, `start` и `finish` на временных каталогах (архив прежнего ключа, права файлов, отказ завершать при DEK на старой версии, значения ключей не печатаются), проверка, что compose и журнал сервиса согласованы со скриптом. Запуск: `python3 -m unittest tools/ops/test_kek_rotate.py` (входит в `tools/docs-checks/run_all.sh`) |
| `restore_drill.py` | Учебное восстановление базы платформы: `run` снимает `pg_dump -Fc` базы `platform_db`, разворачивает дамп в `platform_db_restore`, сверяет журнал аудита по месячным секциям (число и контрольная сумма) и схему, проверяет, что на копии UPDATE, DELETE и TRUNCATE журнала отклонены (ST-09), печатает время дампа и восстановления и удаляет копию (`--keep` оставляет, `drop` удаляет). Время ориентир, не зачёт RTO. Порядок: runbook, раздел 3.6. Нужны Docker и Python |
| `test_restore_drill.py` | Модульные тесты скрипта без Docker: разбор выборок, сверка, защита от пустого журнала, отказ не от триггера неизменяемости не засчитывается, отказ `pg_dump` и `pg_restore`. Запуск: `python3 -m unittest tools/ops/test_restore_drill.py` (входит в `tools/docs-checks/run_all.sh`) |

Весь путь на стенде (ядовитая запись, повторы потребителя, возврат, второй возврат) проверяет `make dlq-check` (`tools/stand-checks/dlq_checks.py`, TC-012).
