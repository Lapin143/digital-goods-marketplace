# frontend

Веб-интерфейс: покупатель, продавец, модератор, оператор поддержки.

| Папка | Состояние | Содержимое |
|---|---|---|
| `web-app/` | Шаги 16 и 17 Ф4: основа, каталог, аккаунт | Приложение на Vite, React 19 и строгом TypeScript ([ADR-026](../docs/05-architecture/adr/ADR-026-frontend-stack.md)): вход через Keycloak (`oidc-client-ts`, код авторизации с PKCE, два менеджера входа `dgm-web` и `dgm-staff`, токены только в памяти), клиент API с `Idempotency-Key`, `If-Match` и разбором `application/problem+json`, защита маршрутов по роли и второму фактору, словарь `src/i18n/ru.json` и несколько своих компонентов. Экраны витрины, кабинета продавца и модерации добавляют шаги 17–19. Образ собирает `docker/Dockerfile.web` (Node собирает, nginx отдаёт готовые файлы), контейнер `web-app` входит в профиль `gateway`, страницу получает только шлюз по mTLS Шаг 17: каталог с поиском, фильтрами и страницами по курсору (`src/screens/storefront`), карточка товара, подтверждение телефона, справка «не пришло письмо» и ограниченная сессия по SMS (`src/screens/account`). |

## Команды

В папке `web-app/` (нужен Node 22.12 или новее; в рабочей среде проекта реестр npm закрыт, поэтому всё ниже выполняют CI и ноутбук):

| Команда | Что делает |
|---|---|
| `npm ci` | Ставит пакеты строго по `package-lock.json` |
| `npm run gen:api` | Создаёт типы запросов и ответов из `docs/06-api/openapi` в `src/api/generated` (в репозиторий не входят) |
| `npm run lint` | ESLint. Правила NFT-7.0: между тегами, в текстовых атрибутах и в строках кода нет текстов для пользователя, они лежат в `src/i18n/ru.json` |
| `npm run typecheck` | `tsc --noEmit`, строгий режим; типы API берутся из `gen:api`, поэтому расхождение с контрактом ловится здесь |
| `npm test` | Vitest и Testing Library |
| `npm run build` | Сборка Vite в `dist` |
| `npm run size` | Размер собранных файлов после gzip: JavaScript не больше 220 КБ, CSS не больше 40 КБ |
| `npm run check` | Всё перечисленное подряд |
| `npm run dev` | Сервер разработки Vite на 5173 (для входа нужен стенд: адрес входа берётся из адреса страницы) |

## Как устроено

- **Вход.** Клиент Keycloak выбирает префикс маршрута, а не роль: `/seller/*`, `/staff/*` и `/work` идут через `dgm-staff` (второй фактор обязателен, токен без `otp` в `amr` кабинет не открывает, интерфейс предлагает войти заново с `prompt=login`), остальное через `dgm-web`, вход по коду из SMS через `dgm-sms`. После возврата из Keycloak (`/oidc/callback/<клиент>`) пользователь попадает на адрес, откуда ушёл; адрес проверяется (только свой сайт).
- **Токены** хранятся в памяти страницы, не в `localStorage` (угроза T-07). После перезагрузки вход проходит заново, тихо, если сессия Keycloak жива.
- **Тексты.** `t('ключ')` из `src/i18n`; ключи проверяет `tsc`. Сообщения об ошибках API берутся из словаря по полю `code` ответа, а не из `detail` (оно написано для разработчика).
- **Каталог.** Фильтры хранятся в адресе страницы (`/products?q=…&type=…&region=RU&priceFrom=…`), поэтому выборкой можно поделиться, а кнопка «назад» возвращает поиск. Запрос уходит по кнопке «Показать», а не на каждую букву. Следующая страница берётся по непрозрачному курсору (`cursor`), который сервер вернул в `page.nextCursor`. Цены вводятся в рублях и уходят в копейках без дробной арифметики. Условный запрос по `ETag` делает браузер сам.
- **Повторы действий.** `Idempotency-Key` создаётся на действие и остаётся прежним, пока исход неизвестен (сбой сети, 5xx, «запрос ещё выполняется»); окончательный ответ сбрасывает ключ (`src/api/requestKey.ts`). Двойное нажатие невозможно: кнопка занята на время запроса.
- **Ограничения частоты.** Время ожидания берётся из `Retry-After` (или `retryAfterAt`), показывается как «через N с» или «через N мин.», кнопка действия недоступна до конца ожидания, обратный отсчёт идёт по часам сервера (заголовок `Date`).
- **Регистрация** открывается тем же входом через Keycloak с параметром `prompt=create`; вход по коду из SMS доступен только со справки «Не пришло письмо» (подвал страницы) и ведёт в ограниченную сессию `/sms`.
- **Права** проверяют шлюз и сервисы. Защита маршрутов нужна, чтобы не показывать разделы, которые всё равно закрыты.
- **Политика содержимого (CSP)** nginx запрещает встроенные скрипты и стили, поэтому в странице их нет, стили лежат в CSS-модулях, подключаемых файлами.
